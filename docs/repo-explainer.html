Educational repo explainer

A benchmark harness for Workspace agents.

This repo tests whether an AI agent can inspect, build, update, and repair durable OpenBB Workspace state through tool calls. It is mainly an eval benchmark, with export and integration adapters layered on top.

  • 1A task is a JSON file with a prompt, allowed tools, fixtures, and hidden success checks.
  • 2The agent emits Workspace tool calls, either one-shot JSONL or interactively.
  • 3The simulator executes those tool calls and the grader scores final Workspace state.
  • 4Results can become reports, model comparisons, rollout JSONL, or SFT data.
512deterministic tasks across the core and build-openbb-apps suites
t0-t4difficulty levels from one action to multi-intent composition

Task

A task is the unit of work. It says what the analyst wants, what Workspace starts with, which tools the model may call, and what final state counts as success.

How to think about this repo

It is not one thing. It is a stack.

Core identity

Benchmark

The source of truth is deterministic evaluation: load a task, run tool calls, grade final Workspace state, record results.

Research use

Model comparison

The evaluator gives every model the same tasks through inline --model provider:model adapters or a models file, tracks pass rates, retries transient failures, and writes reports.

Training use

Adapters

Rollout exports, SFT formats, preference pairs, and the Gym environment reuse the benchmark instead of replacing it.

Task author

Writes task JSON

They define the analyst prompt, fixtures, starting dashboard state, allowed tool set, success checks, metadata, and oracle trace.

Agent runner

Converts prompt into tool calls

An agent can be a Python script, GPT-4.1 through the OpenAI API, Ollama, or a custom local model wrapper.

Workspace runtime

Executes tool calls

The simulator is fast and deterministic. The live MCP smoke runner checks the real sidecar protocol path.

Grader

Scores final Workspace state

The grade checks durable artifacts: widgets, tabs, data args, generated notes, layout, and tool-use discipline.

Run it locally

The important commands are grouped by job.

Validate the benchmark 
uv run workspace-bench validate --suite core --min-tasks 300

What happens during a model comparison

Every model gets the same tasks. The harness measures the resulting Workspace.

Command

uv run workspace-bench \
  --model openai:gpt-4.1-mini \
  --model ollama:qwen3:8b \
  --suite core \
  --timeout 240

What gets written

  • Acomparison.json: machine-readable summary across models.
  • Banalysis.md: human-readable report with task issues and process failures separated.
  • Cchart.svg and chart.png: model performance chart.
  • DPer-task folders with conversations, responses, and tool calls.

Task metadata

Tasks are sliced by action and by workflow.

Capability

What the agent must do: create a widget, instantiate an app, read data, use a skill, delegate work, or repair state.

Workflow

The real work context: earnings prep, client meeting prep, risk review, compliance surveillance, or vendor monitoring.

Domain

The broad area, usually finance or workspace operations.

Subdomain

The narrower desk or function, such as equities, portfolio, macro, compliance, execution, or research.

Task categories

Every task carries a category (workflow kind) and a level (t0-t4 difficulty).

read

Inspect existing state and produce a useful note or answer.

single-widget

Create, update, read, or resize a single widget.

dashboard

Build multi-widget dashboards from analyst requirements.

platform

Use app templates, tabs, parameter groups, generated takeaways, skills, or delegation.

repair

Repair bad Workspace state, wrong tickers, layout overlap, or bad metadata assumptions.

Eval to training

Training is downstream. The benchmark remains the source of truth.

1. Evaluate

Run agents on deterministic tasks. Store final snapshots, traces, grades, and model metadata.

2. Export

Convert runs to rollout JSONL, SFT messages, tool-call JSONL, or preference pairs.

3. Train

Use exported data in your own SFT, preference, or RL pipeline. The repo does not train models by itself.

4. Re-evaluate

Run the trained model back through the same benchmark to measure actual Workspace behavior.

Glossary

Terms in plain English.

Task

One unit of work the agent must solve.

Fixture

Deterministic backend data, such as equities, macro, or portfolio data.

Oracle

A reference tool-call trace that should pass the task.

Noop

A deliberately weak baseline that should fail every task.

pass@k

A task counts as passed if at least one of k repeated attempts passes.

pass^k

A task counts as passed only if all k repeated attempts pass.

Task suite

A directory of tasks, optionally with task_suite.json metadata. Bundled suites: core and build-openbb-apps.

Gym env

A reset/step/render wrapper around the same benchmark episode and grader.
