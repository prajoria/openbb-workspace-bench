# Workspace data

Every referable Workspace ingredient lives here in its own folder, and tasksets select them by identifier through the manifest axes (or per-task
overrides) documented in [TASK-SCHEMA.md](../../../TASK-SCHEMA.md).

## `backends/`

Self-contained fixture backends: catalog (widget definitions, params, options,
apps) plus baked data, loaded by `workspace/fixtures.py`.

| file | slug | notes |
| --- | --- | --- |
| `stark_enterprise_x.json` | `stark-enterprise-x` | Canonical Stark world; transcribed from the stark-industries-demo repo. |
| `stark_enterprise_y.json` | `stark-enterprise-y` | Same catalog, materially different data; regenerated by `scripts/generators/generate_stark_world_y.py`. |
| `support_daloopa_skills.json` | `daloopa` | Fundamentals datapoints. |
| `getting_started.json` | `getting-started` | Transcribed OpenBB backend-examples. |
| `widget_examples.json` | `widget-examples` | Transcribed OpenBB backend-examples. |

The two Stark files share one display name ("Bench Stark Enterprise"); at
most one may be connected per episode.

## `initial_states/`

Materialized `workspace_baseline` states loaded by
`workspace/default_setup.py`: `stark_workspace_a.json` (the everything-mounted
lived-in workspace that the workspace-tasks taskset runs on, regenerated by
`scripts/generators/generate_workspace_states.py`), plus `stark_onboard_a.json`
(PM/research desk) and `stark_onboard_b.json` (trading/ops desk), regenerated
by `scripts/generators/generate_onboard_states.py`. The
`all-stark-enterprise-apps` baseline is built in code from the canonical
catalog (Home plus every Stark app) and has no file.

## `skills/`

One JSON per platform skill (`slug`, `name`, `description`, `content`),
loaded into `WORKSPACE_SKILLS` by `workspace/simulated_workspace.py` and
selectable per suite or task via the `workspace_skills` axis (default: all).
